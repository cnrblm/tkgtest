01

Neden pytest?

15 dakika

Python 101'de testleri kodun altına assert olarak yazdık. Aşağıdaki dosyada fonksiyonda bir hata var ve üç test yazılmış:

eski_testler.py
def gecti_mi(ortalama):
    return ortalama > 60          # hata: >= olmalıydı


assert gecti_mi(60) == True
assert gecti_mi(75) == True
assert gecti_mi(59) == False
print("Tüm testler geçti")
Terminal
python eski_testler.py
Traceback (most recent call last): File "eski_testler.py", line 5, in <module> assert gecti_mi(60) == True AssertionError

İlk assert yanlış çıktı ve program orada durdu. 75 ve 59 testleri hiç çalışmadı; onların geçip geçmediğini bilmiyoruz. Hata mesajı da yalnızca “yanlış” diyor, gecti_mi(60)'ın ne döndürdüğünü söylemiyor.

Testlerin içi değişmiyor. pytest'te de testleri assert ile yazıyoruz. pytest yalnızca testleri bulur, tek tek çalıştırır ve raporlar. Geçen haftaki alıştırmada GitHub Actions'ta gördüğünüz PASSED / FAILED satırları da pytest'in çıktısıydı.

03

İlk test dosyası

20 dakika

pytest'te kod ile testler ayrı dosyalarda durur. pytest-deneme adında bir klasör açın ve içine iki dosya oluşturun:

Klasör
pytest-deneme/
├── notlar.py          ← test edilecek kod
└── test_notlar.py     ← testler
notlar.py
def gecti_mi(ortalama):
    return ortalama >= 60


def harf_notu(puan):
    if puan >= 85:
        return "AA"
    elif puan >= 70:
        return "BB"
    elif puan >= 60:
        return "CC"
    else:
        return "FF"
test_notlar.py
from notlar import gecti_mi, harf_notu


def test_yuksek_not_gecer():
    assert gecti_mi(75) == True


def test_tam_sinirda_gecer():
    assert gecti_mi(60) == True


def test_sinirin_altinda_kalir():
    assert gecti_mi(59) == False


def test_harf_notu_sinirlari():
    assert harf_notu(85) == "AA"
    assert harf_notu(84) == "BB"
    assert harf_notu(60) == "CC"
    assert harf_notu(59) == "FF"
  • from notlar import gecti_mi, harf_notu: notlar.py dosyasındaki fonksiyonları bu dosyada kullanılabilir hale getirir.
  • Her test bir fonksiyondur ve adı test_ ile başlar. Fonksiyonun içinde yine assert var.
  • Testleri sizin çağırmanız gerekmiyor, print("Tüm testler geçti") da gerekmiyor. Bunları pytest yapıyor.

Terminal pytest-deneme klasöründeyken çalıştırın:

Terminal
python -m pytest
============================= test session starts ============================== platform win32 -- Python 3.12.x, pytest-9.x.x, pluggy-1.x.x rootdir: C:\Users\ogrenci\pytest-deneme collected 4 items test_notlar.py .... [100%] ============================== 4 passed in 0.01s ===============================

collected 4 items: pytest dört test buldu. test_notlar.py ....: dosyadaki her test için bir nokta; nokta “geçti” demek. Son satır özet: dört test geçti.

04

pytest testleri nasıl bulur?

10 dakika

pytest'e hangi testleri çalıştıracağını söylemediniz; kendisi buldu. Bunu adlara bakarak yapar:

NeKuralBulunurBulunmaz
Dosyatest_ ile başlar ya da _test.py ile bitertest_notlar.pytestler.py, notlar.py
Fonksiyontest_ ile başlartest_tam_sinirda_gecersinir_kontrolu
KlasörKomutu çalıştırdığınız klasör ve alt klasörleriBaşka bir klasördeyseniz testleriniz bulunmaz
Adı yanlış olan test sessizce atlanır. pytest size “bu fonksiyonu atladım” demez. Aşağıdaki dosyada ikinci fonksiyonun beklentisi yanlış, ama adı test_ ile başlamadığı için hiç çalışmaz:
test_ad.py
from notlar import gecti_mi


def test_yuksek_not_gecer():
    assert gecti_mi(75) == True


def sinir_kontrolu():                 # test_ ile başlamıyor!
    assert gecti_mi(60) == False      # yanlış beklenti, ama hiç çalışmayacak
Terminal
python -m pytest test_ad.py -v
test_ad.py::test_yuksek_not_gecer PASSED [100%] ============================== 1 passed in 0.00s ===============================

İki test yazdınız, pytest bir tane çalıştırdı ve sonuç yeşil. Test sayısı beklediğinizden azsa önce adlara bakın.

06

Başarısız test

20 dakika

notlar.py'de bilerek bir hata yapın: >= yerine > yazın.

notlar.py (hatalı)
def gecti_mi(ortalama):
    return ortalama > 60          # hata: >= olmalıydı
Terminal
python -m pytest
collected 4 items test_notlar.py .F.. [100%] =================================== FAILURES =================================== ____________________________ test_tam_sinirda_gecer ____________________________ def test_tam_sinirda_gecer(): > assert gecti_mi(60) == True E assert False == True E + where False = gecti_mi(60) test_notlar.py:9: AssertionError =========================== short test summary info ============================ FAILED test_notlar.py::test_tam_sinirda_gecer - assert False == True ========================= 1 failed, 3 passed in 0.01s ==========================

Bu çıktıyı yukarıdan aşağı okuyun:

  1. .F..: dört testten ikincisi kaldı, diğer üçü yine çalıştı ve geçti. Düz assert dosyasından farkı bu.
  2. FAILURES başlığının altında kalan testin adı: test_tam_sinirda_gecer.
  3. > işaretli satır: testin kırıldığı satır.
  4. E assert False == True: sol taraf fonksiyondan gelen değer, sağ taraf sizin beklediğiniz değer.
  5. + where False = gecti_mi(60): False değerinin nereden geldiği.
  6. test_notlar.py:9: dosya ve satır numarası.
  7. En altta kısa özet: 1 kaldı, 3 geçti.
Hata mesajı yazmanıza gerek yok. Python 101'de assert ..., "60 alan öğrenci geçmeli" diye mesaj eklemiştik. pytest iki tarafın değerini zaten gösteriyor. İsterseniz yine ekleyebilirsiniz, ama iyi bir test adı çoğu zaman yeterlidir.

Devam etmeden önce notlar.py'yi düzeltip (>=) testlerin yine geçtiğini görün.

07

İyi bir test nasıl yazılır?

15 dakika

Adı, neyi test ettiğini söylesin

Test kırıldığında ilk gördüğünüz şey adıdır. Ad, kodu açmadan neyin bozulduğunu anlatmalı.

Kötüİyi
test_1test_tam_sinirda_gecer
test_gecti_mitest_sinirin_altinda_kalir
test_hatatest_bos_listede_hata_verir

Hazırla, çalıştır, kontrol et

Uzun testleri üç parçaya ayırmak okumayı kolaylaştırır. İngilizce kaynaklarda bu düzenin adı Arrange, Act, Assert (AAA).

test_aaa.py
from notlar import harf_notu


def test_sinifin_harf_notlari():
    # Hazırla
    puanlar = [92, 74, 61, 40]

    # Çalıştır
    harfler = []
    for p in puanlar:
        harfler.append(harf_notu(p))

    # Kontrol et
    assert harfler == ["AA", "BB", "CC", "FF"]
1 passed

Beklenen değeri koddan değil, şartnameden alın

Bir fonksiyonun ne döndürmesi gerektiğini şartname söyler: ödev metni, müşterinin isteği, fonksiyonun üstündeki açıklama. Fonksiyonu çalıştırıp çıkan sonucu teste kopyalarsanız, kod hatalıysa testiniz de hatalı olur ve hatayı onaylamış olursunuz.

  • Her test tek bir durumu denesin. Kırıldığında hangi durumun bozulduğu adından anlaşılsın.
  • Testler birbirine bağlı olmasın. Her test tek başına çalıştırıldığında da geçmeli.
08

Hangi değerleri test etmeli?

25 dakika

Bir fonksiyonu her olası değerle deneyemeyiz. İki fikir hangi değerleri seçeceğimizi söyler:

  • Eşdeğerlik sınıfları: Girdileri, fonksiyonun aynı şekilde davrandığı gruplara ayırın. Her gruptan bir temsilci yeter; 25 derece ile 26 derece aynı şeyi test eder.
  • Sınır değerleri: Hatalar en çok grupların sınırında çıkar (< ile <= karışır). Her sınırın iki tarafını da deneyin.

Örnek: suyun sıcaklığa göre hali.

su.py
def su_durumu(sicaklik):
    if sicaklik < 0:
        return "buz"
    elif sicaklik < 100:
        return "sıvı"
    else:
        return "buhar"
SınıfAralıkTemsilciSınır değerleri
buz0'ın altı-10-1
sıvı0 – 99250, 99
buhar100 ve üstü150100

Tablodaki her hücre bir test olur:

test_su.py
from su import su_durumu


def test_eksi_sicaklikta_buz():
    assert su_durumu(-10) == "buz"


def test_sifirin_hemen_altinda_buz():
    assert su_durumu(-1) == "buz"


def test_sifirda_sivi():
    assert su_durumu(0) == "sıvı"


def test_oda_sicakliginda_sivi():
    assert su_durumu(25) == "sıvı"


def test_yuzun_hemen_altinda_sivi():
    assert su_durumu(99) == "sıvı"


def test_yuzde_buhar():
    assert su_durumu(100) == "buhar"


def test_yuksek_sicaklikta_buhar():
    assert su_durumu(150) == "buhar"
Terminal
python -m pytest test_su.py -v
collecting ... collected 7 items test_su.py::test_eksi_sicaklikta_buz PASSED [ 14%] test_su.py::test_sifirin_hemen_altinda_buz PASSED [ 28%] test_su.py::test_sifirda_sivi PASSED [ 42%] test_su.py::test_oda_sicakliginda_sivi PASSED [ 57%] test_su.py::test_yuzun_hemen_altinda_sivi PASSED [ 71%] test_su.py::test_yuzde_buhar PASSED [ 85%] test_su.py::test_yuksek_sicaklikta_buhar PASSED [100%] ============================== 7 passed in 0.01s ===============================

09

Hata bekleyen testler: pytest.raises

25 dakika

Önce: fonksiyon nasıl hata fırlatır?

Bazı girdiler anlamsızdır: toplamı 0 olan bir şeyin yüzdesi hesaplanamaz. Böyle bir durumda fonksiyon yanlış bir sayı döndürmek yerine hata fırlatmalıdır. Bunu raise ile yaparız. ValueError, “bu değer geçersiz” anlamına gelen hazır bir hata türüdür.

yuzde.py
def yuzde(kisim, toplam):
    if toplam <= 0:
        raise ValueError("toplam pozitif olmalı")
    return kisim / toplam * 100
raise_dene.py
from yuzde import yuzde

print(yuzde(1, 4))
print(yuzde(5, 0))
print("Bu satır hiç çalışmaz")
25.0 Traceback (most recent call last): File "raise_dene.py", line 4, in <module> print(yuzde(5, 0)) File "yuzde.py", line 3, in yuzde raise ValueError("toplam pozitif olmalı") ValueError: toplam pozitif olmalı

raise çalıştığı anda fonksiyon durur, return satırına hiç gelinmez. Hatayı yakalayan kimse yoksa program da durur.

Hatayı test etmek

“Toplam 0 olunca ValueError fırlatmalı” da şartnamenin bir parçası; bunu da test etmeliyiz. assert burada işe yaramaz, çünkü fonksiyon bir değer döndürmüyor. pytest'in pytest.raises aracı tam bunun için var:

test_yuzde.py
import pytest

from yuzde import yuzde


def test_ceyrek():
    assert yuzde(1, 4) == 25.0


def test_sifir_toplam_hata_verir():
    with pytest.raises(ValueError):
        yuzde(5, 0)


def test_negatif_toplam_hata_verir():
    with pytest.raises(ValueError, match="pozitif"):
        yuzde(5, -10)
Terminal
python -m pytest test_yuzde.py -v
collecting ... collected 3 items test_yuzde.py::test_ceyrek PASSED [ 33%] test_yuzde.py::test_sifir_toplam_hata_verir PASSED [ 66%] test_yuzde.py::test_negatif_toplam_hata_verir PASSED [100%] ============================== 3 passed in 0.00s ===============================
  • import pytest: pytest.raises'ı kullanabilmek için dosyanın başına yazılır.
  • with pytest.raises(ValueError): altındaki girintili satır ValueError fırlatırsa test geçer; fırlatmazsa test kalır.
  • match="pozitif": hata mesajının içinde bu kelimenin geçtiğini de kontrol eder. İsteğe bağlıdır.

Fonksiyonda negatif toplamı unutan bir hata olsaydı:

yuzde.py (hatalı)
def yuzde(kisim, toplam):
    if toplam == 0:                   # hata: negatif toplamı kaçırıyor
        raise ValueError("toplam pozitif olmalı")
    return kisim / toplam * 100

DID NOT RAISE: “hata bekliyordum ama fırlatılmadı.” Fonksiyon yuzde(5, -10) için sessizce -50.0 döndürdü. Devam etmeden önce yuzde.py'yi eski haline (toplam <= 0) getirin.

Ondalıklı sayılar: pytest.approx

10 dakika

Bilgisayar ondalıklı sayıları her zaman tam olarak saklayamaz:

Python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
0.30000000000000004 False

Bu yüzden ondalıklı sonuçları == ile karşılaştırmak test kırar. test_yuzde.py'ye şunu ekleyin:

test_yuzde.py (ekleyin)
def test_ucte_bir():
    assert yuzde(1, 3) == 33.33
> assert yuzde(1, 3) == 33.33 E assert 33.33333333333333 == 33.33 E + where 33.33333333333333 = yuzde(1, 3)

Fonksiyon doğru, beklenti de doğru; ama iki sayı birebir aynı değil. pytest.approx “yaklaşık olarak eşit” demektir. abs=0.01 ise en fazla 0.01 farka izin verir:

test_yuzde.py (düzeltilmiş)
def test_ucte_bir():
    assert yuzde(1, 3) == pytest.approx(33.33, abs=0.01)
4 passed
Ne zaman kullanılır? Sonucu ondalıklı olabilecek her hesapta: ortalama, yüzde, KDV, faiz. Sonuç tam sayıysa (25.0, 70) == yeterlidir.

12

Testin testi: bilerek hata koymak

20 dakika

Bütün testler yeşil. Peki testleriniz iyi mi? Hiç test yazmasanız da kırmızı bir şey görmezdiniz. Yeşil, yalnızca “testlerin bulabildiği bir hata yok” demektir.

Bunu ölçmenin yolu: koda bilerek küçük bir hata koyun ve testlerin onu yakalayıp yakalamadığına bakın. su.py'de sicaklik < 100 yerine sicaklik <= 100 yazın:

su.py (hatalı)
def su_durumu(sicaklik):
    if sicaklik < 0:
        return "buz"
    elif sicaklik <= 100:             # hata: < olmalıydı
        return "sıvı"
    else:
        return "buhar"
Terminal
python -m pytest test_su.py
collected 7 items test_su.py .....F. [100%] =================================== FAILURES =================================== _______________________________ test_yuzde_buhar _______________________________ def test_yuzde_buhar(): > assert su_durumu(100) == "buhar" E AssertionError: assert 'sıvı' == 'buhar' E E - buhar E + sıvı test_su.py:25: AssertionError =========================== short test summary info ============================ FAILED test_su.py::test_yuzde_buhar - AssertionError: assert 'sıvı' == 'buhar' ========================= 1 failed, 6 passed in 0.01s ==========================

Hatayı yalnızca tam sınırdaki test_yuzde_buhar yakaladı. (- buhar beklenen, + sıvı gelen değer.) O test olmasaydı, 150 derece testi bu hatayı görmeyecek ve her şey yeşil kalacaktı.

Koda konan hataYakalayan test
sicaklik < 0 → sicaklik <= 0test_sifirda_sivi
sicaklik < 100 → sicaklik <= 100test_yuzde_buhar
sicaklik < 100 → sicaklik < 99test_yuzun_hemen_altinda_sivi

Bu yöntemin adı mutasyon testi: koda küçük değişiklikler (mutasyonlar) yapılır, iyi bir test takımı her birini yakalar. Yakalanmayan bir mutasyon size eksik testi gösterir. Bu haftaki alıştırma, testlerinizi tam olarak bu şekilde ölçüyor.

Denedikten sonra su.py'yi eski haline getirmeyi unutmayın.

13

Sık karşılaşılan hatalar

Başvuru bölümü

No module named pytest

pytest kurulu değil ya da başka bir Python'a kurulmuş. python -m pip install pytest komutunu, testleri çalıştırdığınız python ile çalıştırın.

'pytest' is not recognized / pytest: command not found

Komutu yalnızca pytest diye yazdınız. python -m pytest yazın.

collected 0 items / no tests ran

pytest hiç test bulamadı. Dosya adı test_ ile mi başlıyor? Fonksiyon adları test_ ile mi başlıyor? Terminal doğru klasörde mi? (4. bölüm)
