01

Tekrar eden testler

5 dakika

pytest 101'de su_durumu için sınır değer tablosunu çıkarmış ve her satır için bir test yazmıştık:

test_su.py (geçen hafta)
def test_eksi_sicaklikta_buz():
    assert su_durumu(-10) == "buz"


def test_sifirin_hemen_altinda_buz():
    assert su_durumu(-1) == "buz"


def test_sifirda_sivi():
    assert su_durumu(0) == "sıvı"

# ... dört test daha, hepsi aynı kalıpta

Yedi fonksiyonun hepsi aynı şeyi yapıyor: bir sıcaklık veriyor, bir sonuç bekliyor. Değişen yalnızca iki değer. Yeni bir sınır eklemek istediğinizde yine üç satırlık bir fonksiyon kopyalıyorsunuz. Bu tekrarın iki sorunu var: dosya uzadıkça okumak zorlaşıyor, kopyalarken de hata yapmak kolaylaşıyor.

Bu sayfadaki örnekler geçen haftaki pytest-deneme klasöründe çalışır. su.py ve yuzde.py orada duruyor olmalı; yoksa pytest 101'den tekrar oluşturun.
02

@pytest.mark.parametrize

20 dakika

parametrize, tek bir test fonksiyonunu bir değer listesindeki her satır için ayrı ayrı çalıştırır. Sınır değer tablosu doğrudan teste dönüşür:

test_su.py
import pytest

from su import su_durumu


@pytest.mark.parametrize("sicaklik, beklenen", [
    (-10, "buz"),
    (-1, "buz"),
    (0, "sıvı"),
    (25, "sıvı"),
    (99, "sıvı"),
    (100, "buhar"),
    (150, "buhar"),
])
def test_su_durumu(sicaklik, beklenen):
    assert su_durumu(sicaklik) == beklenen
Terminal
python -m pytest test_su.py -v
collecting ... collected 7 items test_su.py::test_su_durumu[-10-buz] PASSED [ 14%] test_su.py::test_su_durumu[-1-buz] PASSED [ 28%] test_su.py::test_su_durumu[0-sıvı] PASSED [ 42%] test_su.py::test_su_durumu[25-sıvı] PASSED [ 57%] test_su.py::test_su_durumu[99-sıvı] PASSED [ 71%] test_su.py::test_su_durumu[100-buhar] PASSED [ 85%] test_su.py::test_su_durumu[150-buhar] PASSED [100%] ============================== 7 passed in 0.12s ===============================

Bir fonksiyon yazdık, pytest yedi test çalıştırdı. Nasıl okunur:

  • "sicaklik, beklenen": parametrelerin adları, virgülle ayrılmış tek bir metin olarak.
  • Listedeki her (…, …) bir test durumudur. İlk değer sicaklik'e, ikincisi beklenen'e gider.
  • Test fonksiyonu aynı adlarla parametre alır: def test_su_durumu(sicaklik, beklenen).
  • Köşeli parantez içindeki [-10-buz], o çalışmada kullanılan değerlerdir. (Türkçe harfler ı gibi kodlanıyor; bir sonraki bölümde düzelteceğiz.)

Bir değer hatalı olursa yalnızca o satır kalır. su.py'de sicaklik < 100 yerine sicaklik <= 100 yazın:

test_su.py .....F. [100%] =================================== FAILURES =================================== __________________________ test_su_durumu[100-buhar] ___________________________ sicaklik = 100, beklenen = 'buhar' ... > assert su_durumu(sicaklik) == beklenen E AssertionError: assert 'sıvı' == 'buhar' ... FAILED test_su.py::test_su_durumu[100-buhar] - AssertionError: assert 'sıvı' ... ========================= 1 failed, 6 passed in 0.09s ==========================

pytest hangi satırın kaldığını ([100-buhar]) ve o çalışmadaki değerleri (sicaklik = 100, beklenen = 'buhar') gösteriyor. Devam etmeden önce su.py'yi düzeltin.

Yeni bir sınır eklemek artık tek satır: listeye (100.5, "buhar") gibi bir satır eklersiniz.
03

Okunur test adları: ids

10 dakika

04

parametrize ile hata bekleyen testler

15 dakika

Geçerli girdiler ve hata vermesi gereken girdiler ayrı testlerde durmalı, çünkü kontrol ettikleri şey farklı: biri bir değer bekliyor, diğeri bir hata. Her ikisi de parametrize edilebilir. Geçen haftaki yuzde fonksiyonu için:

test_yuzde.py
import pytest

from yuzde import yuzde


@pytest.mark.parametrize("kisim, toplam, beklenen", [
    (1, 4, 25.0),
    (3, 3, 100.0),
    (0, 5, 0.0),
])
def test_yuzde(kisim, toplam, beklenen):
    assert yuzde(kisim, toplam) == beklenen


@pytest.mark.parametrize("toplam", [0, -1, -10])
def test_gecersiz_toplam_hata_verir(toplam):
    with pytest.raises(ValueError):
        yuzde(5, toplam)

  • Üç parametre de olabilir; her satırda üç değer olur.
  • Tek parametrede satırlar demet değil, düz değerdir: [0, -1, -10].
05

Kısa bir ara: sözlük (dict)

10 dakika

Bu haftanın alıştırmasında sepetteki her ürün bir sözlük. Liste değerleri sırayla tutar; sözlük ise her değere bir ad (anahtar) verir. Süslü parantezle yazılır:

sozluk.py
ogrenci = {"ad": "Ayşe", "not": 85}

print(ogrenci["ad"])         # anahtarla okunur
print(ogrenci["not"])

ogrenci["not"] = 90          # değiştirilir
print(ogrenci)

sinif = [                    # sözlüklerden oluşan bir liste
    {"ad": "Ayşe", "not": 85},
    {"ad": "Ali", "not": 45},
]
for o in sinif:
    print(o["ad"], o["not"])
Ayşe 85 {'ad': 'Ayşe', 'not': 90} Ayşe 85 Ali 45

Şimdilik bu kadarı yeterli: {"anahtar": değer} ile oluşturmak, sozluk["anahtar"] ile okumak ve sözlüklerden oluşan bir listede for ile dolaşmak. Alıştırmadaki sepet tam olarak böyle bir liste: [{"urun": "çay", "fiyat": 20, "adet": 2}, …].

06

Kapsam (coverage)

20 dakika

Yeterince test yazdığınızı nasıl anlarsınız? İlk soru şu: testleriniz kodun her satırını en az bir kez çalıştırıyor mu? Hiç çalışmayan bir satırdaki hatayı hiçbir test bulamaz. Bunu ölçen araç pytest-cov:

Terminal
python -m pip install pytest-cov
bilet.py
def bilet_ucreti(yas):
    ucret = 100
    if yas < 18:
        ucret = 50
    return ucret


def grup_indirimi(kisi_sayisi):
    if kisi_sayisi >= 10:
        return 20
    return 0
test_bilet.py
from bilet import bilet_ucreti, grup_indirimi


def test_cocuk_bileti():
    assert bilet_ucreti(10) == 50
Terminal

07

Dal kapsamı (branch coverage)

15 dakika

bilet_ucreti'ne bakın. Yalnızca 10 yaşla test ettik. if yas < 18 doğru çıktı, ucret = 50 çalıştı; her satır çalışmış oldu. Ama koşulun yanlış çıktığı yol, yani yetişkin bileti, hiç denenmedi. Bir if'in iki yoluna dal denir. --cov-branch ekleyin:

Terminal
python -m pytest test_bilet.py --cov=bilet --cov-branch --cov-report=term-missing
Name Stmts Miss Branch BrPart Cover Missing ------------------------------------------------------ bilet.py 9 0 4 1 92% 3->5 ------------------------------------------------------ TOTAL 9 0 4 1 92%
  • Branch: dosyada 4 dal var (iki if, her birinin iki yolu).
  • BrPart: bir yolu hiç denenmemiş koşul sayısı (1).
  • 3->5: 3. satırdaki koşuldan doğrudan 5. satıra atlama yolu hiç çalışmadı. Yani koşul hiç yanlış çıkmadı.
test_bilet.py (ekleyin)
def test_yetiskin_bileti():
    assert bilet_ucreti(30) == 100
Name Stmts Miss Branch BrPart Cover Missing ------------------------------------------------------ bilet.py 9 0 4 0 100% ------------------------------------------------------ TOTAL 9 0 4 0 100%
Döngülerin de dalı vardır: en az bir kez dönmesi ve hiç dönmeden geçilmesi. Boş liste testi, döngünün “hiç dönmeden” dalını çalıştırır.
08

%100 kapsam yetmez

15 dakika

Dal kapsamı %100. Şimdi pytest 101'deki gibi koda bilerek bir hata koyun: bilet.py'de yas < 18 yerine yas <= 18 yazın ve aynı komutu çalıştırın:

test_bilet.py .... [100%] Name Stmts Miss Branch BrPart Cover Missing ------------------------------------------------------ bilet.py 9 0 4 0 100% ------------------------------------------------------ TOTAL 9 0 4 0 100% ============================== 4 passed

Kod hatalı, kapsam %100 ve bütün testler yeşil. Kapsam yalnızca “bu satır çalıştı mı?” sorusunu cevaplar, “sonuç doğru kontrol edildi mi?” sorusunu değil. 10 ve 30 yaşı denedik ama tam sınırı (18) hiç denemedik.

AraçCevapladığı soruBulamadığı
Satır kapsamıHer satır en az bir kez çalıştı mı?Koşulların öbür yolu, sınırlar, yanlış kontrol
Dal kapsamıHer koşulun iki yolu da denendi mi?Sınırlar, yanlış kontrol
Mutasyon testiKoda konan küçük hataları testler yakalıyor mu?Daha yavaş; ama en sıkı ölçü

Kapsam düşükse testleriniz kesinlikle eksiktir. Kapsam %100 ise testleriniz belki iyidir. Bu yüzden bu haftanın alıştırmasında ikisi birlikte ölçülüyor: önce kapsam, sonra hatalı sürümler. Devam etmeden önce bilet.py'yi düzeltin.

Kapsamı hedef yapmayın. Her satırı çalıştırıp sonucunu kontrol etmeyen bir test (bilet_ucreti(10), assert olmadan) kapsamı artırır ama hiçbir hatayı yakalamaz.
09

Kısa giriş: hypothesis

15 dakika

Şimdiye kadar test değerlerini biz seçtik. hypothesis başka bir yol sunar: bir özellik yazarsınız (“her zaman doğru olması gereken bir şey”), hypothesis yüzlerce girdi üretip özelliği bozan bir girdi arar.

Terminal
python -m pip install hypothesis
ortalama.py
def ortalama(notlar):
    toplam = 0
    for i in range(len(notlar)):
        toplam = toplam + notlar[i]
    return toplam / len(notlar)

Özellik: “Hangi notlar olursa olsun, ortalama en küçük not ile en büyük not arasında kalır.”

test_ortalama.py
from hypothesis import given, strategies as st

from ortalama import ortalama


@given(st.lists(st.integers(min_value=0, max_value=100), min_size=1))
def test_ortalama_en_kucuk_ile_en_buyuk_arasinda(notlar):
    sonuc = ortalama(notlar)
    assert min(notlar) <= sonuc <= max(notlar)
test_ortalama.py::test_ortalama_en_kucuk_ile_en_buyuk_arasinda PASSED [100%]

@given(...) “bu testi şu türden girdilerle çalıştır” der: 0–100 arası tam sayılardan oluşan, en az bir elemanlı listeler. Test bir kez göründü ama hypothesis onu yüz farklı listeyle çalıştırdı. Şimdi döngüye bir hata koyun: range(len(notlar)) yerine range(1, len(notlar)):

notlar = [1] ... > assert min(notlar) <= sonuc <= max(notlar) E assert 1 <= 0.0 E + where 1 = min([1]) E Failing test case: test_ortalama_en_kucuk_ile_en_buyuk_arasinda( E notlar=[1], E ) ... ============================== 1 failed

hypothesis hatayı bulmakla kalmadı, onu gösteren en basit girdiyi de buldu: tek elemanlı [1]. İlk eleman hiç toplanmadığı için ortalama 0 çıktı. Devam etmeden önce ortalama.py'yi düzeltin.

Bu haftalık bu kadar. hypothesis'i alıştırmada kullanmanız gerekmiyor; isterseniz deneyebilirsiniz. Önemli olan fikir: bazen tek tek değerler yerine “her zaman doğru olan” bir kural test edilir.
10

Sık karşılaşılan hatalar

Başvuru bölümü

In test_x: function uses no argument 'notu'

parametrize'daki ad ile test fonksiyonunun parametre adı aynı değil: @pytest.mark.parametrize("notu, gecti", …) ama def test_x(not_, gecti). İkisini aynı yazın.

error: unrecognized arguments: --cov=bilet

pytest-cov kurulu değil. python -m pip install pytest-cov. Alıştırma klasöründe: python -m pip install -r requirements.txt.

CoverageWarning: Module biletler was never imported / No data was collected

--cov='dan sonra yazdığınız ad, test edilen dosyanın adıyla aynı değil. bilet.py için --cov=bilet yazılır; .py olmadan.

Bütün parametrize satırları kalıyor

Değerlerin sırası, adların sırasıyla aynı mı? "sicaklik, beklenen" yazıp satırlara ("buz", -10) koyarsanız her satır yanlış eşleşir.

2. Eksik kapsamı bulun

Aşağıdaki iki test geçiyor. Kapsamı ölçün, eksik kalan satırı bulun ve onu çalıştıran testi ekleyin. Sonra 500 km sınırını da düşünün: kapsam %100 olduğunda > 500 yerine >= 500 yazılmış bir hatayı testleriniz yakalıyor mu?

kargo.py
def kargo_gunu(mesafe_km):
    if mesafe_km < 0:
        raise ValueError("mesafe negatif olamaz")
    gun = 1
    if mesafe_km > 500:
        gun = 2
    return gun
test_kargo.py
from kargo import kargo_gunu


def test_yakin_sehir():
    assert kargo_gunu(100) == 1


def test_uzak_sehir():
    assert kargo_gunu(800) == 2
Terminal
python -m pytest test_kargo.py --cov=kargo --cov-branch --cov-report=term-missing
Name Stmts Miss Branch BrPart Cover Missing ------------------------------------------------------ kargo.py 7 1 4 1 82% 3
Çözümü göster

3. satır (raise) hiç çalışmadı: negatif mesafe denenmemiş. Sınırları da ekleyince:

test_kargo.py
import pytest

from kargo import kargo_gunu


@pytest.mark.parametrize("mesafe, gun", [
    (0, 1),
    (100, 1),
    (500, 1),
    (501, 2),
    (800, 2),
])

3. Haftanın alıştırması: Kapsam ve Parametrize

Geçen haftaki gibi hafta04/alistirma.py'deki kod doğru, testlerini siz yazıyorsunuz. Üç fonksiyon var: indirim_orani, sepet_toplami ve en_pahali_urun. Sepet, sözlüklerden oluşan bir liste (5. bölüm).

  1. Elinizdeki değişiklikleri commit'leyip push edin. Sonra GitHub'da kendi fork'unuzda Sync fork → Update branch düğmesine basın.
  2. Yeni haftayı alın, klasöre girin ve bu haftanın paketlerini kurun:

  3. alistirma.py'yi okuyun; her fonksiyonun üstündeki açıklama şartnamedir. test_alistirma.py'de örnek bir test hazır.
  4. Testlerinizi yazın ve çalıştırın:
    Terminal
    python -m pytest -v
  5. Bitince gönderin ve fork'unuzun Actions sekmesinde hafta04 satırına bakın:
    Terminal
    git add .
git commit -m "hafta04 testleri"
git push
