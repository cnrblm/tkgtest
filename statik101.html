01

Kodu çalıştırmadan test

10 dakika

pytest ile yazdığımız testler kodu çalıştırır ve çıkan sonuca bakar. Buna dinamik test denir. Bazı sorunları bulmak için kodu çalıştırmak gerekmez; okumak yeterlidir. Kodu (ya da gereksinim belgesini) çalıştırmadan incelemeye statik test denir. İki yolu vardır: insanın okuması (gözden geçirme) ve bir aracın okuması (statik analiz).

Dinamik testStatik test
Kod çalışıyor mu?EvetHayır
Örneklerpytest, mutasyon testi, hypothesisGözden geçirme, ruff, mypy
Ne zaman?Kod çalışır hâle gelinceKod yazılırken; gereksinimler için kod yazılmadan önce bile
Ne bulur?Arızayı (yanlış çıktı), oradan geriye kusuru ararızKusuru doğrudan: kullanılmayan değişken, yanlış karşılaştırma, aşırı karmaşık kod

İkisi birbirinin yerine geçmez. Statik analiz, programın ne yapması gerektiğini bilmez: 18 yerine 17 yazılmış bir sınırı bulamaz. Testler ise hiç çalışmayan bir satırdaki ya da “şimdilik çalışan” bir kötü alışkanlıktaki sorunu göremez. Bu sayfada ikincisini öğreniyoruz.

Neden önemli? Bir hata ne kadar erken bulunursa o kadar ucuza düzeltilir. Statik analiz, kodu kaydettiğiniz anda, daha test bile yazmadan çalışır.

Docstring (PEP 257)

İkinci sürümdeki üç tırnaklı metinler docstring'dir: dosyanın ya da fonksiyonun ilk satırı olarak yazılan açıklama. Yorumdan (#) farkı, Python'un onu saklamasıdır. VS Code fonksiyonun üstüne gelince onu gösterir; Python kabuğunda help(gecti) yazarsanız şunu görürsünüz:

Help on function gecti in module gecti: gecti(puan, baraj_notu=50) Puan baraj notuna eşit veya büyükse True döndürür.

PEP 257'nin özü: tek satırlık docstring üç tırnakla açılır ve kapanır, fonksiyonun ne yaptığını bir cümleyle söyler. Nasıl yaptığını anlatmaz.

04

Ruff: ilk kontrol

15 dakika

Bu kuralları gözle denetlemek yorucu. Linter denen araçlar kodu okuyup kurallara uymayan yerleri listeler. Biz ruff kullanacağız: hızlı, tek araç, hem denetliyor hem biçimlendiriyor. Yeni bir klasör açın:

Terminal
mkdir statik-deneme
cd statik-deneme
python -m pip install ruff
ortalama.py
import os


def ortalama(notlar):
    toplam = 0
    for n in notlar:
        toplam = toplam + n
    ort = toplam / len(notlar)
    return toplam
Terminal
python -m ruff check ortalama.py
F401 [*] `os` imported but unused --> ortalama.py:1:8 | 1 | import os | ^^ help: Remove unused import: `os` ... F841 Local variable `ort` is assigned to but never used --> ortalama.py:8:5 | 6 | for n in notlar: 7 | toplam = toplam + n 8 | ort = toplam / len(notlar) | ^^^ 9 | return toplam | ... Found 2 errors. [*] 1 fixable with `--fix` (1 unsafe fix available with `--fix --unsafe-fixes`).

Her uyarı aynı biçimde okunur:

ParçaAnlamı
F841Kuralın kodu. Harf kural ailesini, sayı kuralı gösterir.
Local variable `ort` is assigned to but never usedNe bulduğu: ort'a değer verilmiş ama hiç kullanılmamış.
ortalama.py:8:5Dosya, satır, sütun.
[*]Ruff bunu kendisi düzeltebilir (7. bölüm).

İkinci uyarıya dikkat edin. ort'un kullanılmaması bir “süs” sorunu değil: fonksiyon ortalama yerine toplamı döndürüyor. Kullanılmayan bir değişken çoğu zaman bir hatanın izidir. Ruff bunu, siz daha test yazmadan buldu.

Bir kodun ne anlama geldiğini, neden kötü olduğunu ve nasıl düzeltileceğini ruff'a sorabilirsiniz:

Terminal
python -m ruff rule F841
# unused-variable (F841) ... ## Why is this bad? A variable that is defined but not used is likely a mistake, and should be removed to avoid confusion. ...
Neden python -m ruff? pytest'te olduğu gibi: Windows'ta ruff komutu bazen bulunamaz, python -m ruff her zaman çalışır.

06

Uyarı değil, hata

20 dakika

Ruff'ın bazı uyarıları zevk meselesi gibi görünür. Bazıları ise çalışıyor gibi görünen koddaki gerçek hatalardır. İki örnek:

B006: değiştirilebilir varsayılan değer

sepet.py
def sepete_ekle(urun, sepet=[]):
    sepet.append(urun)
    return sepet


print(sepete_ekle("çay"))
print(sepete_ekle("simit"))
Terminal
python sepet.py
['çay'] ['çay', 'simit']

İkinci çağrıda sepet boş olmalıydı ama ilk çağrının çayı hâlâ orada. Varsayılan değer ([]) fonksiyon tanımlanırken bir kez oluşturulur ve sonraki bütün çağrılar aynı listeyi paylaşır. Ruff bunu çalıştırmadan görür:

sepet.py:1:29: B006 Do not use mutable data structures for argument defaults

Düzeltmenin bilinen kalıbı: varsayılan olarak None verin, listeyi fonksiyonun içinde oluşturun.

sepet.py
def sepete_ekle(urun, sepet=None):
    if sepet is None:
        sepet = []
    sepet.append(urun)
    return sepet
['çay'] ['simit']

E722: çıplak except

bolme.py
def guvenli_bol(a, b):
    try:
        return a / bb
    except:
        return None


print(guvenli_bol(10, 2))
None

10 / 2 sonucu None çıktı. Kodda bir yazım hatası var (bb), Python bunun için NameError fırlatıyor, ama türü yazılmamış except: her hatayı yakalayıp sessizce yutuyor. Zen'in “hatalar sessizce geçmemeli” satırı tam olarak bu. Ruff ikisini de buluyor:

bolme.py:3:20: F821 Undefined name `bb` bolme.py:4:5: E722 Do not use bare `except` Found 2 errors.

Düzeltme: yazım hatasını giderin ve yalnızca beklediğiniz hatayı yakalayın:

bolme.py
def guvenli_bol(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return None


print(guvenli_bol(10, 2))
print(guvenli_bol(10, 0))
5.0 None

Otomatik düzeltme ve biçimlendirme

15 dakika

ruff check --fix

[*] işaretli uyarıları ruff kendisi düzeltebilir. ortalama.py'ye dönün:

Terminal
python -m ruff check --fix ortalama.py
ortalama.py:7:5: F841 Local variable `ort` is assigned to but never used Found 2 errors (1 fixed, 1 remaining). 1 unsafe fix available with `--fix --unsafe-fixes`.

import os silindi. F841 ise kaldı, çünkü düzeltmesi güvensiz (unsafe): ruff'ın önerisi ort = kısmını silmek, yani sonucu hiçbir yere yazmadan bölme yapmak. Asıl düzeltme return ort yazmak; bunu ancak kodu okuyan biri bilebilir. --unsafe-fixes kullanmayın, kalan uyarıları kendiniz düzeltin.

ruff format

Boşluklar, tırnaklar, boş satırlar gibi biçim konularıyla biçimlendirici (formatter) ilgilenir. Aşağıdaki dosyada ruff check hiçbir şey bulmaz ama dosya dağınık:

kare.py
def kare( x ):
  return x*x
sayilar=[1,2,3]
for s in sayilar :
    print( kare(s) )

Önce neyi değiştireceğine bakın (--diff dosyaya dokunmaz):

Terminal
python -m ruff format --diff kare.py
--- kare.py +++ kare.py @@ -1,5 +1,7 @@ -def kare( x ): - return x*x -sayilar=[1,2,3] -for s in sayilar : - print( kare(s) ) +def kare(x): + return x * x + + +sayilar = [1, 2, 3] +for s in sayilar: + print(kare(s)) 1 file would be reformatted

- ile başlayan satırlar silinecek, + ile başlayanlar eklenecek. Uygulamak için --diff olmadan çalıştırın:

Terminal
python -m ruff format kare.py
1 file reformatted
KomutNe yapar?Kodun anlamını değiştirir mi?
ruff formatYalnızca görünüş: boşluk, girinti, tırnak, boş satırHayır, hiçbir zaman

08

Karmaşıklık

20 dakika

Bir fonksiyondaki her if, elif, for, while ve except akışı ikiye ayırır. Döngüsel karmaşıklık (cyclomatic complexity) bu ayrımların sayısının bir fazlasıdır: fonksiyonun içinden geçen, birbirinden bağımsız yolların sayısı. pytest 102'deki dal kapsamı ile aynı fikir: karmaşıklık arttıkça, her yolu denemek için gereken test sayısı da artar.

otopark.py
def otopark_ucreti(saat, abone):
    if saat <= 0:
        return 0
    if abone:
        if saat <= 2:
            return 0
        else:
            if saat <= 6:
                return 30
            else:
                return 70
    else:
        if saat <= 2:
            return 30
        else:
            if saat <= 6:
                return 60
            else:
                return 100

Altı if, karmaşıklık 1 + 6 = 7. ruff.toml'da sınırı 5 koymuştuk:

otopark.py:1:5: C901 `otopark_ucreti` is too complex (7 > 5)

Koda dikkatli bakınca bir düzen görülüyor: abone olan herkes, abone olmayanın ödediğinden 30 TL eksik ödüyor. Önce mevcut davranışı bir testle sabitleyin, sonra kodu değiştirin:

test_otopark.py
import pytest

from otopark import otopark_ucreti


@pytest.mark.parametrize(
    "saat, abone, beklenen",
    [
        (0, False, 0),
        (2, False, 30),
        (6, False, 60),
        (7, False, 100),
        (0, True, 0),
        (2, True, 0),
        (6, True, 30),
        (7, True, 70),
    ],
)
def test_otopark_ucreti(saat, abone, beklenen):
    assert otopark_ucreti(saat, abone) == beklenen
8 passed
otopark.py (yeni)
def otopark_ucreti(saat, abone):
    if saat <= 0:
        return 0
    if saat <= 2:
        ucret = 30
    elif saat <= 6:
        ucret = 60
    else:
        ucret = 100
    if abone:
        ucret = ucret - 30
    return ucret
Terminal
python -m pytest test_otopark.py -q
python -m ruff check otopark.py
8 passed All checks passed!

Davranış aynı (testler hâlâ yeşil), karmaşıklık 5'e indi, iç içe yapı düzleşti. Kodun davranışını değiştirmeden yapısını iyileştirmeye yeniden düzenleme (refactoring) denir. Testler olmadan yapılan yeniden düzenleme kumarla aynı şeydir: bir şeyi bozup bozmadığınızı bilemezsiniz.

Sınır kaç olmalı? Tek bir doğru sayı yok. Ruff'ta varsayılan sınır 10; biz başlangıç örnekleri kısa olduğu için 5 kullanıyoruz. Önemli olan sayı değil, ekipçe bir sınır seçip ona uymak.

Kısa giriş: tip ipuçları ve mypy

15 dakika

Python bir değişkenin türünü sormaz; yanlış türü ancak o satır çalışınca fark eder. Tip ipuçları (PEP 484) ile bir fonksiyonun ne aldığını ve ne döndürdüğünü yazabilirsiniz. Python bunları çalışırken yok sayar; mypy ise kodu çalıştırmadan denetler.

Terminal
python -m pip install mypy
fiyat.py
def kdv_ekle(fiyat: float) -> float:
    return fiyat * 1.2


def etiket(fiyat: float) -> str:
    return "Fiyat: " + kdv_ekle(fiyat)

fiyat: float “bu parametre ondalıklı sayı”, -> str “bu fonksiyon metin döndürür” demek. python fiyat.py hiçbir hata vermez, çünkü etiket hiç çağrılmıyor. Ruff da bir şey bulmaz. mypy ise bulur:

Terminal
python -m mypy fiyat.py
fiyat.py:6: error: Unsupported operand types for + ("str" and "float") [operator] Found 1 error in 1 file (checked 1 source file)

Metin ile sayı toplanamaz. Düzeltmesi "Fiyat: " + str(kdv_ekle(fiyat)). Bundan sonra mypy Success: no issues found der.

mypy'nin en çok işe yaradığı yer, bazen None döndüren fonksiyonlardır:

ort.py
def not_ortalamasi(notlar: list[int]) -> float | None:
    if len(notlar) == 0:
        return None
    return sum(notlar) / len(notlar)


def harf_ver(notlar: list[int]) -> str:
    if not_ortalamasi(notlar) >= 50:
        return "geçti"
    return "kaldı"
ort.py:8: error: Unsupported operand types for <= ("int" and "None") [operator] ort.py:8: note: Left operand is of type "float | None"

float | None “ondalıklı sayı ya da None” demek. mypy, boş listede None >= 50 karşılaştırmasının yapılacağını ve programın çökeceğini, hiçbir test yazılmadan söylüyor.

Dikkat: mypy varsayılan olarak tip ipucu yazılmamış fonksiyonların içine bakmaz. İpucu yoksa “Success” demesi, kodun doğru olduğu anlamına gelmez. Bu haftanın alıştırmasında mypy yok; isteyen deneyebilir.

Statik testin öbür yarısı, kodu bir insanın okumasıdır. GitHub'daki pull request'lerde ekip arkadaşının değişikliği okuyup yorum yazması en yaygın biçimidir. Araçlar ezberlenebilecek kuralları denetler; insan ise şunu sorar: bu kod doğru şeyi mi yapıyor?

Başkasının kodunu (ya da kendi kodunuzu) okurken kısa bir kontrol listesi işe yarar:

  1. Şartnameyi okudum. Kod her maddeyi karşılıyor mu?
  2. Sınırlarda ne oluyor? (< mı <= mı, boş liste, 0, negatif sayı)
  3. Hata durumları ele alınmış mı? Yanlış girdide ne oluyor?
  4. Adlar ne yaptığını anlatıyor mu? x, liste2, sonuc yerine ne yazılabilirdi?
  5. Bu değişikliği deneyen bir test var mı?
  6. Ruff temiz mi? (Araçların bulacağı şeyler için insan vakti harcanmasın.)
Gözden geçirme kişiyi değil, kodu eleştirir. “Burada yanlış yapmışsın” yerine “Boş listede burası sıfıra bölmüyor mu?” diye sorun.

Sık karşılaşılan hatalar

Başvuru bölümü

'ruff' is not recognized / ruff: command not found

Komutu python -m ruff check ... biçiminde yazın.

No module named ruff

Ruff kurulu değil: python -m pip install ruff. Alıştırma klasöründe: python -m pip install -r requirements.txt.

N802 gibi uyarılar bende çıkmıyor

Ruff, ruff.toml'u bulamıyor. Denetlediğiniz dosyayla aynı klasörde (ya da bir üst klasörde) ruff.toml var mı? Dosyanın adı tam olarak ruff.toml mu (ruff.toml.txt değil)?

F821 Undefined name `NotListesi`

Bir parametrenin adını değiştirdiniz ama fonksiyonun içindeki kullanımlarını değiştirmediniz. VS Code'da adın üstüne gelip F2 (Rename Symbol) ile değiştirirseniz bütün kullanımlar birlikte değişir.

--fix bazı uyarıları düzeltmedi

Normal. Yalnızca [*] işaretli, güvenli düzeltmeler otomatik yapılır. Kalanlar düşünmeyi gerektirir; python -m ruff rule KOD ile kuralı okuyup elle düzeltin.

VS Code'da biçimlendirdim ama ruff format --check hâlâ kırmızı

Eklentinin kullandığı ruff sürümü farklı olabilir. Terminalde alıştırma klasöründe python -m ruff format alistirma.py çalıştırın; GitHub'da kullanılan sürüm requirements.txt'teki sürümdür.

Temizledim, şimdi testler kırmızı

Bir değişiklik davranışı bozmuş. Hangi test kaldıysa o fonksiyondaki son değişikliğinize bakın. Bu yüzden her küçük değişiklikten sonra testleri çalıştırın.

3. Haftanın alıştırması: Statik Analiz

Bu hafta hafta06/alistirma.py'deki kod çalışıyor ama kötü yazılmış. Testler hazır; siz kodu temizliyorsunuz. Fonksiyonların adlarını ve ne yaptıklarını değiştirmiyorsunuz, yalnızca nasıl yazıldıklarını.

  1. Elinizdeki değişiklikleri commit'leyip push edin. Sonra GitHub'da kendi fork'unuzda Sync fork → Update branch düğmesine basın.
  2. Yeni haftayı alın, klasöre girin ve bu haftanın paketini kurun:
    Terminal
    git pull
cd hafta06
python -m pip install -r requirements.txt
  3. Önce durumu görün:
    Terminal
    python -m pytest -v
python -m ruff check alistirma.py
  4. alistirma.py'yi temizleyin. Her değişiklikten sonra python -m pytest -v çalıştırın.
  5. Bitince gönderin ve fork'unuzun Actions sekmesinde hafta06 satırına bakın:
    Terminal
    git add .
git commit -m "hafta06 temizlik"
git push
